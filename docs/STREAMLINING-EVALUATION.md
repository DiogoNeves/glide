# Public streamlining behavior screen — 3 October 2026

This screen compares selected public Glide/Obsidian/Developer policies with fictional evidence. It does not transmit the private instance's instruction or financial-state files. The opt-in runner is in [examples/streamlining-screen](../examples/streamlining-screen/README.md); seven fake-CLI tests validate its evidence and failure handling without model calls.

## First frozen comparison

The initial comparison requested `gpt-5.5`, high reasoning, with Codex CLI 0.133.0. All 50 cases have baseline and candidate answers with validated schemas and zero actual tool activity. Review assesses simulated responses and proposed actions, not executed writer calls, source permissions or deliveries. Both variants preserve the assessed major source, writing and external-action boundaries.

## Final instruction clarification

The final policies clarify evidence-grounded drafts, named atomic-job APIs with all required transaction fields, and no-change Developer daily silence with first-five calibration and actionable-access-gap exceptions. These changes apply broadly; original comparisons and failures are retained. Later policy variants are identified by their actual payload hashes, and reused unchanged baseline receipts are explicitly linked rather than counted as new executions.

The final targeted comparison requests `gpt-6.1-sol`, high reasoning, on app-bundled Codex 0.160.0. Its memory, Developer and context groups cover 24 cases per arm: 23 full rubric passes and the same one unscored dependency gap (case 32) in each arm. An independent reviewer confirmed complete atomic fields in case 13, silence in case 44 and grounded placeholders in case 31. Case 48's reversible comparison is a minimal pass; the baseline is more explicit about its comparison criteria.

Unchanged baseline memory/Developer receipts were reused with exact prompt/hash linkage; context has a fresh pair. Intermediate snapshots remain separately identified by payload hashes. The entire original 50-case screen was not repeated under the final instructions. The initial comparison used a different model and CLI, so the change in its misses cannot be attributed solely to the instruction clarification. These targeted results support the sampled behaviors, not universal quality equivalence.

## Limited newer-model check

Codex CLI 0.160.0 bundled with the desktop app supports the requested `gpt-6.1-sol`, high reasoning. A public recovery/fictional-finance subset contains 12 cases per arm, including the two reserved challenges. Both arms satisfy those case rubrics, return validated schemas and make zero actual tool calls. Both include the closing-debt projection omitted by the older-model runs. Model and CLI changed together; this limited observation cannot isolate a model-generation effect or establish general superiority. Homebrew CLI 0.133.0 rejected that model; its failed attempts were not counted as successful runs.

## Interpreting savings and quality

The first daily eight-case pair consumed 16,523 baseline / 12,408 candidate input tokens and 1,764 / 1,698 output tokens. Memory inputs were nearly unchanged at 15,244 / 15,237 because those cases required preserved protocol details. Cached input differs between runs; prompt groups share context, sampling varies and latency includes harness work. Do not convert these few measurements into a general cost or speed claim.

Deterministic runtime and copied-store comparisons supply separate evidence for exact history, data preservation, writer guards and rollback. The real synthetic filesystem-boundary probe passed with the app-bundled executable; native-source permissions, private-policy model behavior, sustained scheduled coaching and a second physical host require their own observations. Passing this public screen does not verify those surfaces.
