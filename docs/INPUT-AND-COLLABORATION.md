# Input and collaboration

Talk to Glide normally. You do not need to open or edit the internal `Now` view, queues or managed records. Glide HQ is its internal workspace; readable links are available when you want to inspect evidence. The agent brings questions and reviews into conversation, then records your answer.

A shared note is optional. If a decision or draft benefits from a working document, agree on its location in your ordinary writing area, outside Glide HQ, and the sections the agent may change. New shared documents clearly identify AI assistance in frontmatter and in their visible text. Your own writing remains yours. The label does not grant permission to rewrite it.

The [canonical checklist](../templates/Glide%20HQ/Checklists/Input%20and%20Collaboration.md) defines the delivery, ownership and receipt boundary. Questions that need no shared document remain in conversation; there is no second inbox for you to maintain. Automatic knowledge mode changes ingestion policy, not this boundary.

## Install or upgrade

Install the checklist and merge its short routing references into active agent instructions, the memory protocol, review skills and daily/weekly/decision procedures. Inspect local customizations first. Record any selected collaboration destination and edit scope in private instance context; these are agent-readable choices, not new runtime configuration keys. No collaboration directory or public example note needs to be created automatically.

Review saved automation prompts as well as their templates: any required question must be delivered in the configured conversation, with enough context to answer there. Update only authorized jobs. Existing internal queues, proposals, views and receipts stay internal. An internal draft becomes a shared document only when actually needed and within an agreed scope; retain the internal history and connect the new working surface without bulk migration.

The runtime, schema, permissions and proposal → apply → receipt contract are unchanged. A checkbox or edited note is not a writer receipt. Preserve previous instruction hashes for rollback; do not roll back the owner's newer decisions or authored text. Validate the [synthetic scenarios](../examples/input-surface-cases.json) before treating a routing update as verified behavior, and observe the next real request for input.
